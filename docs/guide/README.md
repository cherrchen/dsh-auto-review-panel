## 支持矩阵为什么是精确版本清单

本插件的宿主半部与浏览器半部都要在上游**没有 semver 承诺**的接缝上工作：客户端槽位名、Connection 通道、组合行的挂载语义。所以 `peerDependencies` 只列真正跑过全套验证的版本，启动时也会再查一遍：宿主的版本不在清单上，或者若干个 `@deepseek-ai/dsh-*` 混装了不同版本，那么被门禁的 `auto-review-panel` 行**不启动**，组合退化成"没装这个插件"，并打印一条说明。诊断办法见[故障排查](../troubleshooting/unsupported-dsh-release.md)，理由见 [ADR-0001](../decisions/ADR-0001-dsh-compat-contract.md)。

## 组合里实际发生了什么

`cordis.patch.yml` 只做一件事：在上游 bundle 的行列表里插入本插件的三行——兼容性门禁、面板宿主半部、以及挂在裸包名上的 client 图锚点。它**不禁用**任何上游行：面板是观察面，不替换任何现有能力。三行的职责与"为什么裸包名行不可省"见[故障排查](../troubleshooting/client-bundle-not-in-boot-graph.md)与 `tests/patch.spec.ts`。

## 审查历史存在哪里、存多久

面板捕获的每条审查——请求全文、四节解析结构、推理、裁决、`hostOutcome` 佐证——**以明文 JSONL 落盘**在 `<DSH_HOME>/auto-review-panel/v1/`（默认 `~/.dsh/auto-review-panel/v1/`，`$DSH_HOME` 环境变量覆盖）。目录权限 `0700`、文件 `0600`，界面里位置以 `~/.dsh/…` / `$DSH_HOME/…` 符号化拼写显示。

- **重启不丢**：会话维度恢复——同 `$DSH_HOME` 下再次打开某会话，其历史照常列出；Auto Review 已停用或该会话不再用 Auto preset 时也照常展示（有记录优先于空态）。
- **未关联记录全局可见**：上游 `deny + never` 拦截的调用到不了会话关联，这些记录（恰是最高风险的一批）落进 `unassigned.jsonl`，在任何会话视图里都能翻到。
- **默认不限量**：三个留存轴——每会话记录数 / 保留会话数 / 总大小 MB——出厂全为 `0` = 不限。想收紧：插件管理页本插件条目 → `auto-review-panel` 行的 Configure 页直接改；保存立即生效并跑一次维护（压实、淘汰最旧会话、总量裁剪）。
- **清理**：同一设置页底部的"清理全部历史"（有确认弹窗）删除全部历史文件 + 当前内存记录，留存设置保留。历史丢失不影响插件工作——持久化是纯旁路，任何写入失败都不会改变审查与工具执行。
- **隐私边界**：落盘内容含发送给审查器的完整请求文本与推理原文，明文、不加密、不上传——共享机器或多用户环境请按本地敏感文件对待；不方便落盘时可在设置页把"每会话记录数"设为很小的值或将三轴留在 `0` 并定期清理（没有"关闭持久化"开关——面板自己读历史也是经这条路径）。
- **没有跨会话浏览**：无会话视图只显示当前进程内存里的记录——按会话恢复是刻意的边界（见 [ADR-0004](../decisions/ADR-0004-review-record-persistence.md)）。

## 各安装来源的差异

- **npm / tarball（发布后）**：预构建产物，即装即用。
- **GitHub**：装的是源码，`add` 时由包内 `prepare` 脚本自动构建（直接打包 `src/`，不做类型检查），`allowBuilds` 需含本包；不带 ref 会跟随 `main` 分支的最新提交，写 `#vX.Y.Z` 这样的版本 ref 锁住内容。
- **从源码安装**：pnpm `link:` 链接本地 checkout，依赖在本仓库已装好，无需 `allowBuilds`；需要先 `pnpm build` 生成 `lib/`（未纳入 Git）。

用源码仓库跑 DSH 时 `dsh` 不在 PATH 里，把命令里的 `dsh` 换成 `pnpm dsh`。
